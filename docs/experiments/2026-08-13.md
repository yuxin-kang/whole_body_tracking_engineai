### 用户 Play 结果

用户在客户端 Play `model_20500.pt` 后报告：“这个特别好”，“完全可以用了”。用户进一步确认本次实验最关键的经验是：不要让机器人在动作执行过程中因为正常的大幅姿态变化被提前终止；策略需要经历完整动作以及动作后的恢复阶段。

测试命令：

```bash
python scripts/rsl_rl/play.py \
--task Tracking-Flat-T800-Baseline-LeftFrontKick-CompleteEpisode-HeightFallOnly-v0 \
--motion_file data/npz/traj_eng_50hz_episode_complete/left_front_kick_002_terminal_hold_1s.npz \
--load_run 2026-08-13_09-55-57_left_front_kick_002_complete_episode_heightfall_a4000_j7440 \
--checkpoint model_20500.pt \
--num_envs 1 \
--play_from_start true
```

### 相对上一版本的关键改动

- 移除姿态摔倒终止：`fall_orientation.limit_angle = 1.2 rad` → `fall_orientation = null`。
- 继续保留高度摔倒终止：机器人根节点高度低于 `0.4 m` 时重置。
- 动作数据、episode 长度、从第 0 帧开始播放、PPO 参数、环境数量和奖励配置均与对照 run 保持一致。

### 实验结论

- 对正蹬这类包含明显瞬时躯干倾斜的动作，不能把动作过程中的大姿态变化直接当作失败并提前重置，否则策略无法充分学习踢出、收腿和恢复阶段。
- 本实验采用“允许动作过程中的姿态变化，仅在根节点高度低于 `0.4 m`、即实际倒地时重置”的终止方式；该设置对应用户确认“完全可以用了”的 `model_20500.pt`。
